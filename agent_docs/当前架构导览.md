# 当前架构导览

本文从当前代码结构出发，解释一次 Agent 运行如何跨越模块。它补充阶段实现记录，
不替代[后续开发路线](./后续开发路线.md)或具体 Phase 文档。

## 一、整体调用链

```text
应用入口（main.py / 调用方）
  │
  ├─ AgentSession：组装当前问题、短期历史和可选长期记忆
  │
  └─ AgentLoop：执行一次 Agent run
       ├─ AgentState：保存输入、每个模型响应和工具执行轨迹
       ├─ ContextBuilder → ConversationProjector：准备本次模型上下文
       ├─ LLM 接口 → OllamaClient：访问模型服务
       ├─ ToolExecutor → ToolRegistry → Tool：检查并执行工具
       └─ AgentEvent → Logger：输出可读日志或 JSONL trace
  └─ evaluation/：在运行之后读取轨迹、事件与结果，评分但不参与决策

可选的计算器规划路径：`CalculatorPlanner` → 模型一次生成 JSON 计划 → 整份预校验
→ `ToolExecutor` 逐步执行并核验 → `PlanRunResult.render()` 查看状态；不写入
`AgentLoop` 的 trajectory，不接管默认会话或 JSONL trace。
```

应用通过 `AgentSession` 管理多个用户轮次；若直接使用 `AgentLoop`，则由调用方
自己管理每次调用的消息输入。`main.py` 现在是交互式对话入口，
离线功能实验则集中在 `experiments/`。

## 二、模块职责与依赖方向

### `agent/`：控制循环、状态和上下文

- `session.py`：接收一轮用户输入，选取短期历史；仅在 Agent 成功完成后提交本轮新增消息。
  可选长期记忆检索也是显式触发的。
- `loop.py`：反复调用模型；识别最终回答、处理空响应、执行工具调用并按 `max_steps` 停止。
- `state.py`：保存 `AgentState`、`AgentStep`、输入消息和工具执行事实。
- `conversation.py`：将轨迹投影成规范的模型对话，不决定是否回放推理、裁剪或摘要。
- `context.py`：为单次模型调用建立上下文策略；当前支持默认关闭或回放最近待续接的 reasoning。
- `planner.py`：可选的计算器 plan-then-execute 路径，整份计划预校验与执行时工具结果验证。

### `llm/`：provider-neutral 类型与模型适配

- `base.py` 定义 `Message`、`ToolCall`、`ModelResponse` 和抽象 `LLM` 接口。
- `ollama.py` 负责把通用消息和工具转换为 Ollama `/api/chat` 格式，并将响应转换回来。
- `embedding.py` 适配 Ollama `/api/embed`；embedding 与聊天接口分离。

`agent/` 与 `runtime/` 使用通用类型，不应直接依赖 Ollama 的 wire format。替换模型
provider 时，适配器负责协议转换。

### `tools/` 与 `runtime/`：工具描述和执行边界

- `tools/base.py` 定义工具名称、说明、JSON Schema 参数和 handler；`registry.py` 管理已注册工具。
- `runtime/executor.py` 提供当前可用工具，并在执行时再次检查 capability；之后进行参数校验和 handler 调用。
- `runtime/recovery.py` 将工具错误分类；可选 `RecoveryPolicy` 由 `AgentLoop` 用于限制失败后模型纠正次数，也可只在下一次请求中注入暂态自检提示；不重放工具、不改变规范轨迹。
- `runtime/validation.py` 使用 JSON Schema Draft 2020-12 校验不可信模型参数。
- `runtime/result.py` 用 `ToolResult` 表达工具成功或可预期的工具失败。
- `runtime/permissions.py` 为显式注册的 `tools/filesystem.py` 只读工具限制相对路径、受信任目录和读取字节数；可选精确相对路径白名单进一步收紧资源授权。这不是通用沙箱，默认入口不注册该工具。
- `runtime/commands.py` 为显式注册的 `tools/commands.py` 固定命令限制 argv、工作目录、环境、时长及管道输出；进程依然拥有 OS 权限，默认入口不注册该工具。

模型可以提出工具调用，但工具是否可用、参数是否合法以及如何执行由 Python Runtime
控制。工具失败结果可以作为 observation 返回给模型；Runtime 层异常则沿调用链抛出。

### `memory/`：短期对话历史和显式长期检索

- `conversation.py` 保存已完成轮次的快照，按完整轮次淘汰，并可在读取时施加字符预算。
- `long_term.py` 提供 namespace 范围的 SQLite 文本记忆和字面检索。
- `semantic.py` 提供显式 embedding、SQLite 向量持久化和 cosine top-k 排序。
- 写入长期记忆、发起检索由应用控制；检索结果作为不可信参考数据加入 user 上下文，
  不作为 system instruction，也不授予工具能力。

### `observability/`：运行事实的可见性

`AgentLoop` 发出结构化事件。`HumanReadableLogger` 适合终端观察，`FileDebugLogger`
追加完整可读轨迹到调试文件，`JsonlTraceLogger`
以版本化 JSONL 记录事件，`RunMetrics` 汇总模型/工具调用、错误、可用 token 数据和耗时。
默认 JSONL trace 不写原始对话内容；显式打开内容记录时才会保存原文。

### `experiments/`：理解和验证行为

确定性离线实验使用脚本化模型或可控 embedding，不要求 Ollama；带 `live`、`--chat`
或说明真实模型的实验需要本地服务和相应模型。`evaluation/` 提供 Phase 13 的声明式用例和汇总评分；
脚本模型的通过率不代表模型质量，在线实验也是小样本观察。

## 三、一次工具调用如何流过系统

以模型请求计算器工具为例：

1. 当前轮输入由 `AgentSession`（或调用方）交给 `AgentLoop.run()`。
2. `AgentState` 记录外部输入；`ContextBuilder` 从轨迹取得规范消息。
3. `AgentLoop` 把消息和 `ToolExecutor.available_tools()` 提供的工具传给 `LLM.chat()`。
4. `OllamaClient` 序列化请求；模型返回后，适配器生成 `ModelResponse`，其中可含 `ToolCall`。
5. `AgentLoop` 把该响应记入 `AgentStep`，再交由 `ToolExecutor` 检查工具可用性、参数 schema 并执行。
6. 执行结果包装为 `ToolResult`，与原始 `ToolCall` 一起关联到当前 step，并投影为 `role="tool"` 消息。
7. 下一次循环从更新后的轨迹构造模型上下文；模型可以继续调用工具，也可以给出最终回答。
8. 运行期间事件被 Logger 观察。若 `AgentSession` 收到已完成结果，它仅提交本轮新增的规范消息到短期记忆。

简化表示：

```text
Message → ModelResponse(ToolCall) → ToolExecutor → ToolResult
   ↑                                               │
   └────── trajectory → 下一次模型上下文 ←──────────┘
```

## 四、必须区分的几种表示

| 表示 | 用途 | 不负责什么 |
|---|---|---|
| `AgentState.trajectory` | 保留外部输入、模型响应（含 thinking）和工具执行的运行事实 | 不直接等同于 provider 消息列表 |
| `ConversationProjector` 输出 | 确定性生成 assistant/tool 规范对话 | 不应用上下文策略，不回放 thinking |
| `ContextBuilder` 输出 | 生成某一次模型调用实际使用的上下文 | 不改写 canonical trajectory |
| `ConversationMemory` | 保存成功完成的历史轮次快照 | 不保存 raw thinking，也不提供精确 token 预算 |
| `LongTermMemory` 检索结果 | 应用显式选择后提供的参考数据 | 不自动写入，也不授予工具 capability |

这些边界让完整调试轨迹、正式对话历史与单次调用策略不会互相冒充。

## 五、当前已知范围和后续关注

- reasoning replay 默认关闭；当前策略不意味着已证明回放能提升模型质量。
- 短期和长期记忆的预算以字符为单位，不是完整 prompt token 预算。
- SQLite 语义检索使用小规模线性扫描；相似度用于排序，不是答案正确概率。
- `main.py` 负责连续对话与会话记忆；离线交互验证见 `experiments/interactive_cli_experiment.py`，Phase 13 评测由独立 `evaluation/` 和两个实验入口承担。
- Phase 9 计算器范围、Phase 10 有界工具纠正/可选自检与 Phase 13 已完成；Phase 11A/B/C 是可选的只读文件、固定命令及精确文件授权边界，完整权限/沙箱仍未实现；其余状态以路线文档为准。
