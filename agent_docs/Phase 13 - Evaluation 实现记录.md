# Phase 13 — 独立任务评测（13A / 13B）

## 作用与边界

新增 `evaluation/`，只在 Agent 运行**之后**核对可观察事实；不把评分反馈放进模型上下文，也不赋予新工具权限。13A 用脚本模型验证评测器和 Runtime 的确定性基线；13B 使用同一评分接口在 Ollama 上固定题目重复运行。脚本模型的 100% 通过率只说明控制流程与评分条件一致，**不代表真实模型质量**。

## 评分设计

- `EvaluationCase` 声明题目、停止原因、工具调用及参数的**精确顺序**、最终答案（精确字符串或正则）、预期工具错误数、步骤上限，以及可选的 SQLite 长期记忆输入和预期检索文本。不能只凭答对数字就判为正确使用工具。
- `evaluate` 为每个样本创建新的 AgentLoop、工具注册表与临时记忆库；普通题直接运行 Agent，记忆题由 AgentSession 显式检索。实际调用从轨迹中的模型响应读取（包括未成功执行的未知工具），检索事实从 session 读取，指标与耗时来自 Phase 12 的 `AgentFinished`。异常记录为失败样本，保留 `run_id` 和已发出的事件指标。
- `EvaluationReport.render()` 输出逐项事实与失败原因、成功率、步骤、工具次数、错误、token 和耗时；只要有一次模型响应未报告某类 token，该类本次/汇总成本就是 `unknown`，不将部分和当完整成本。日志输出包含题目答案、工具参数和检索文本，**可能含敏感信息**，本阶段不自动落盘。
- 正则答案只能对显式、可检查的格式做近似判断，不能代替语义人工判分；例如在线数字用数字边界避免把 `119` 误当 `19`。错误的“未知”或错误归因可能需要更强的案例/人工复核。记忆题包含其他项目的干扰项，先验证实际检索内容，再判回答；检索文本不授予权限。

## 可读实验（仓库根目录）

```bash
.venv/bin/python experiments/evaluation_experiment.py
.venv/bin/python experiments/evaluation_live_experiment.py --help
.venv/bin/python experiments/evaluation_live_experiment.py --model qwen3.5:9b --repeats 3
```

首条无需 Ollama：7 个通过用例分别展示算术、工具选择/参数、未知工具、无需工具、步骤上限、缺失事实和干扰项归因；额外的错误参数/答案、异常和错误归因用例必须判 FAIL，验证评分器本身。第二条只显示参数；第三条需已运行 Ollama 和已安装的聊天模型。在线每一重复和每个题目都有单独 run ID；显示每轮成功率、总成功率、token 与延迟以及重复间成功率和单次延迟的标准差。失败时命令退出码为 1；服务不可用也会被记录为失败样本，**不要把连接失败解读为模型能力不足**。模型版本、硬件、服务负载、参数和题目必须固定才能作对比；此处样本很小，没有统计显著性保证。缺失 token 不参与零填充。

## 重要发现与后续方案

- 本地 `qwen3.5:9b` / Ollama 在线验证（2 轮 × 5 题）得到 10/10，通过条件包含工具名/参数、答案与检索记录。总计 prompt/completion token 为 9278/1080；平均每次 run 5606.3ms，标准差 11555.0ms；第一次加法 run 约 40 秒，后续约 1–4 秒。冷启动与负载显著影响延迟；这不是多模型比较，也不能据此声称稳定 100% 正确率。运行时各 run ID 在终端报告中可见，不自动持久化。
- `AgentRunResult` 没有总耗时字段；事件 `AgentFinished.duration_ms` 已包含单调时钟测量，评测只读取事件而不改变 Agent API。`RunMetrics.prompt_tokens` / `completion_tokens` 可分别未知，也可能只是部分响应之和；评测另外按轨迹检查报告完整性。
- 实际工具调用与工具结果不同：未知工具调用照样在轨迹中，但产生 `tool_not_found` 结果；评分必须同时看调用和错误数。
- 当前在线评分是固定、可复查的小型行为测试，不是开放任务基准；如需研究检索质量，应增加来源 ID、预算淘汰、缺失事实/误归因变体和人工复核；如需成本对比，应固定模型与硬件，记录更大样本及 provider 的完整 token 数据。未来可导出经过脱敏的评测结果，但不应把 JSONL trace 当作 checkpoint。
