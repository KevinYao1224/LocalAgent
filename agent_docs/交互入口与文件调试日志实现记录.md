# 交互入口与文件调试日志

## 本阶段的调用链

`main.py` 用 `OllamaClient → AgentLoop → AgentSession` 组装一次进程内会话；
`ToolRegistry` 注册四则运算工具，`ToolExecutor` 执行经过校验的工具调用。
一次用户输入触发一个 run，只有完成的轮次会被 `AgentSession` 写入
`ConversationMemory`。默认保留最近 5 个完整轮次，`:clear` 清空该会话记忆。
`:help`、`:clear`、`:exit` 由入口处理，不发给模型。`--prompt` 用相同的
会话与组件链执行单轮任务，失败时进程退出码为 1。

`FileDebugLogger` 实现 `AgentLogger`：包装现有 `HumanReadableLogger`，将完整可读
事件追加到指定 UTF-8 文件，自动创建父目录，每个事件后刷新；`with` 负责关闭。
默认路径 `logs/agent-debug.log`，可以用 `--log-file` 更改。文件中有 run/step ID、
thinking、回答、工具参数/结果和错误原文；默认终端只显示答案或停止原因。
`--verbose` 在终端额外输出截短的可读轨迹；`--trace-jsonl` 可同时保存原有
结构化事件，保持 JSONL 默认不记内容的行为。调试日志为原文，使用真实任务时
需按需管理文件的访问和保存期限。

## 运行及观察

在项目根目录，先启动 Ollama 并准备 `qwen3.5:9b`：

```bash
.venv/bin/python main.py --log-file /tmp/opencode/chat-debug.log
# 输入：计算 (12 + 7) * 5
# 输入：刚才的结果是多少？
# 输入：:clear
# 输入：:exit
```

另开终端观察文件：`tail -f /tmp/opencode/chat-debug.log`。比较两轮不同的
run ID、第二轮的 Initial messages 和工具结果，观察跨轮会话的投影。
单次脚本调用可使用 `.venv/bin/python main.py --prompt "计算 12 + 7"`。

不需 Ollama 的确定性、人类可读实验：

```bash
.venv/bin/python experiments/interactive_cli_experiment.py
```

它检查连续轮次、工具调用、异常后继续、max_steps 不提交、`:clear` 后遗忘、
退出及 EOF、指定文件创建与再次打开时追加；还检查命令不进入事件日志。
实验最后以替换的离线模型运行真正的 `main()` 参数入口，验证 `--prompt`、
`--log-file` 和 `--trace-jsonl` 的组合。

## 后续关注

目前交互入口只暴露计算器工具与短期记忆；长期记忆仍保持显式 API，
如需在 CLI 添加检索或持久化，应先设计写入和选择策略，并为其增加独立实验。
会话记忆的独立在线场景仍位于
`experiments/conversation_memory_live_experiment.py`。
