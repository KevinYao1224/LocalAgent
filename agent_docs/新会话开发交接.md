## 2. 当前架构

Phase 7A 新增外层 `AgentSession`：system prompt + ConversationMemory.retrieve()
+ 当前 user → AgentLoop.run()；completed 后仅提交本轮新增 canonical messages。
每轮 State 独立，默认保留最近 5 个完整轮次；system 不进入窗口，raw thinking
不跨轮保存。详见 [Phase 7A 实现记录](./Phase%207A%20-%20Conversation%20Memory%20实现记录.md)。

```text
Application
    │
    ▼
AgentLoop ──→ AgentState / Trajectory
    ├──→ ContextBuilder ──→ 本轮 model context
    │       └──→ ConversationProjector ──→ canonical messages
    ├──→ ToolExecutor ──→ ToolRegistry ──→ Tool
    ├──→ Observability Events ──→ Logger
    └──→ LLM Interface ──→ OllamaClient
```

Trajectory 保存：

```text
InputMessage
AgentStep
    ├── ModelResponse
    ├── ReasoningBlock | None
    └── ToolExecution(call, result)[]
```

职责边界：

```text
AgentState
    记录运行事实和控制状态，不构造 messages

ConversationProjector
    从 Trajectory 确定性生成 canonical conversation
    不回放 thinking、不裁剪、不摘要、不使用 memory

ContextBuilder
    为单次 LLM 调用构造策略上下文
    当前只处理 reasoning_replay=off | latest_pending

AgentLoop
    驱动模型调用、把模型响应和工具回复记录到 AgentState、控制终止
```

`AgentRunResult.messages` 始终是 canonical conversation。即使 LLM 调用临时
使用了 reasoning replay，该瞬时上下文也不会伪装成正式历史。

## 3. Phase 6C 的实现

新增 `agent/context.py`：

```text
ReasoningReplayPolicy
    OFF
    LATEST_PENDING

ContextBuildResult
    messages
    replayed_reasoning_step
    reasoning_replayed

ContextBuilder
```

默认 policy 是 `OFF`。

`LATEST_PENDING` 最多选择一个最近 reasoning block，且要求：

```text
adapter capability == supported
ReasoningBlock.replayable == True
provider 与当前 LLM 精确匹配
model 已知且与当前 LLM 精确匹配
tool step 的每个 observation 已产生，或它是 thinking-only step
```

没有 content、tool call 和 reasoning 的 inert empty step 可以跳过；遇到新的非空
决策 step 后不会越过它回放更旧 reasoning，以免陈旧推理污染新决策。

Replay 时：

```text
tool-call step
    → thinking 合并到同一条 assistant tool-call message

thinking-only step
    → 创建 content="" 的 assistant thinking message
```

构建过程不修改 Trajectory 或 canonical projection。

## 4. 必须保持的不变量

```text
1. 默认 reasoning replay 始终为 off。
2. replayable=True 只表示 adapter 能传输，不表示策略已启用。
3. thinking 不等于最终回答。
4. thinking 不参与权限、参数验证或工具授权。
5. ConversationProjector 保持 policy-free。
6. AgentRunResult.messages 只代表 canonical conversation。
7. 不支持 replay 的 provider 必须安全降级。
8. provider/model 不匹配或 model identity 未知时不得 replay。
9. tool observation 不完整时不得 replay。
10. raw thinking 不应无限期进入上下文。
11. DecisionMemo 继续暂缓，不要按旧设计恢复。
```

2026-09-23 上述离线回归和编译检查通过。真实 Ollama 首次请求曾在 180 秒后
`ReadTimeout`；预热模型后拆分复跑 Phase 7B 四个场景，全部通过，最终查询 prompt
tokens 分别为 92、117、132、2182，与既有基线一致。

Phase 7C 的 4000 字符在线预算实验也通过：16677 字符的工具轮次被完整排除，指标
为 selected=0、dropped=1、characters=0；一次性工具阻止模型重新获取事实后，模型
回答 `UNKNOWN`，第二轮两次模型调用累计 708 prompt tokens，而原始标记仍完整保存
在 Memory。实验位于 `experiments/history_character_budget_live_experiment.py`。

重要发现：若工具仍可重复成功，模型会主动重新调用工具并取得标记，这不是 Memory
泄漏。评测 Memory 时必须把工具可见性和事实重取路径纳入条件。

Phase 7D 已进一步封闭旧工具调用越权路径：`ToolExecutor.execute()` 必须确认工具
仍存在于执行时刻的 `available_tools()`。即使 Registry 保留工具、历史保留旧调用
名称和正确参数，禁用后也只会返回 `tool_not_available`，不会进入参数验证或 handler。
详见 `experiments/tool_capability_experiment.py` 和 Phase 7D 实现记录。

## 7. Phase 7 后续范围

Phase 7A 已完成最小会话 Memory。Phase 7B 新增
`experiments/conversation_memory_live_experiment.py`，真实 `qwen3.5:9b` 的 3 次
小样本中，跨轮引用、事实更新、完整轮次淘汰和长工具结果均成功。普通 recall
最终查询为 92 prompt tokens，保留约 1.67 万字符工具结果后为 2182 tokens。
这证明 max_turns 不能控制单轮超长 observation。

Phase 7C 已完成检索级 history character budget：从最新轮次向前选择不超过预算
的完整 suffix，并暴露 selected/dropped/characters。它不是精确 token budget，
不计 system/current user/tools schema；超预算的单个最近轮次整体排除，不截断
tool exchange，也不自动摘要。

`ConversationMemory.select(budget)` 返回 `ConversationMemorySelection`，默认
`retrieve()` 语义不变；`AgentSession` 可用 `history_character_budget` 配置每轮
检索，并通过 `last_history_selection` 读取指标。算法遇到第一个放不下的轮次立即
停止，以保证结果始终是最新连续 suffix；预算只影响读取，不删除已保存轮次。

可用 `.venv/bin/python main.py` 通过标准 AgentSession 和 HumanReadableLogger
可视化运行全部 Phase 7B 场景；`--scenario recall|fact-update|eviction|long-tool`
可单独核验。Logger 在该入口仅预览长文本，截断不影响真实上下文和 Memory。
